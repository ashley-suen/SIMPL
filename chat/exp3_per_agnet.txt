● 好，那在 2048 token 硬限制下，目前有两条路：

  路线 A：分离 Agent 编码（推荐，根本解决方案）
  - 每个 agent 独立做一次 LLM forward pass（共享权重），自己用完 2048 token
  - 6 个 agent 的 hidden representation 再通过 cross-attention 融合
  - 彻底消除 token 竞争，每个 agent 都有 50 步完整历史
  - 需要较大架构重构：修改 llm_motion_model.py 和 av2_llm_dataset.py

  路线 B：压缩格式（临时方案）
  - max_length 从 1500 改到 2048（+548 token）
  - 步幅采样（每 2 步取 1 步）把每个 agent 压到 25 步
  - 结果：focal 约 600 token，剩余 ~1300 token 分给 5 个邻居，每个约 11 步
  - 实现简单，但邻居信息仍然严重不足

  路线 B 的根本问题：即使再压缩，5 个邻居在单个序列里分到的 token
  依然少得可怜（约 11 步），无法提供足够的上下文。而且 focal agent 的历史也从 50
   步缩减到 25 步，精度下降。

  结论：如果目标是让模型真正学会多智能体交互，路线 A 是唯一合理选择。路线 B
  只能缓解截断问题，无法从根本上解决。

● Plan A 架构设计：分离 Agent 编码

  核心思路

  旧架构：
    [header + agent0 + agent1 + ... + agent5] → 单次 LLM → mask pooling → MLP
    问题：共享 token budget，后面的 agent 被截断

  新架构：
    agent0 prompt → LLM ┐
    agent1 prompt → LLM ├→ cross-attention → MLP → 轨迹
    ...                 │
    agent5 prompt → LLM ┘
    优点：每个 agent 独享 2048 token，无截断

  ---
  数据层变化（av2_llm_dataset.py）

  旧：构建一个长 prompt，所有 agent 拼接，输出 input_ids: [L]

  新：为每个 agent 构建独立 prompt，输出 input_ids: [N, L]

  每个 agent 的 prompt 格式：
  [scene header]  # 时间、地点等静态信息，约 50 token
  [该 agent 自身的 0~50 步历史]  # 约 1200 token（focal）或更短

  - N 个 agent 各自独立 tokenize，统一 pad 到相同长度 L（≤ 2048）
  - 删除 agent_token_masks（不再需要）
  - agent_valid 改为：该 agent 是否存在于场景中（非零 mask）

  ---
  模型层变化（llm_motion_model.py）

  forward(input_ids[B,N,L], attention_mask[B,N,L]):

    1. Reshape → [B*N, L]
    2. LLM encoder（共享权重）→ hidden [B*N, L, H]
    3. Mean pool（或 [CLS] token）→ [B*N, H]
    4. Reshape → [B, N, H]   ← 每个 agent 一个 representation
    5. Social Cross-Attention: Q=K=V=[B,N,H] → [B,N,H]
    6. MLP head → [B, N, K, 60, 2]（K 个预测模式）

  Step 5 是核心新增模块，让 agent 之间能够"互相看见"，提供社交上下文。

  ---
  模块设计

  ┌────────────────┬──────────────────────────────────────┬────────────────┐
  │      模块      │                 描述                 │     参数量     │
  ├────────────────┼──────────────────────────────────────┼────────────────┤
  │ LLM Backbone   │ SmolLM-135M/360M，共享权重           │ 冻结 or        │
  │                │                                      │ 部分解冻       │
  ├────────────────┼──────────────────────────────────────┼────────────────┤
  │ Agent Pooling  │ mean pool 或 CLS token               │ 0              │
  ├────────────────┼──────────────────────────────────────┼────────────────┤
  │ Social         │ 标准 Multi-Head                      │ ~4× H²         │
  │ Attention      │ Attention，num_heads=4               │                │
  ├────────────────┼──────────────────────────────────────┼────────────────┤
  │ MLP Head       │ H → 256 → K×60×2                     │ 小             │
  └────────────────┴──────────────────────────────────────┴────────────────┘

  ---
  内存/计算分析

  - 每次 forward：B × N 个短序列（约 1300 token）并行通过 LLM
  - 等效 batch size = B × N = 4 × 6 = 24（实际比旧架构更节省，因序列更短）
  - Cross-attention 计算量：O(N² × H) 极小，N≤6 可忽略

  ---
  需要修改的文件

  data_av2/av2_llm_dataset.py   ← 重写 prompt 构建逻辑，输出 [N, L]
  simpl/llm_motion_model.py     ← 添加 social attention，修改 forward
  train_llm.py                  ← 数据 shape 适配（通常改动很小）

  ---
  实现顺序建议

  1. 先改 dataset：让 __getitem__ 输出 input_ids: [N, L]，验证 prompt 内容正确
  2. 再改 model：添加 social cross-attention，调整 forward 签名

  4. 训练：从头训练（旧 checkpoint 不兼容）
